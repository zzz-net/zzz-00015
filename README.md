# 维修派工管理系统 (Maintenance Dispatch System)

一个基于 Python + Tkinter 的维修派工单管理桌面应用，支持工单登记、派工、接单、完工、验收、排班管理、批量改派、备件库存、上门改约、到场确认等完整流程。

## 上门改约 & 到场确认模块

### 功能入口

**调度员（张调度 / u001）** 登录后可在以下位置操作：

1. **工单列表 Tab** → 选中已派单的工单 → 点击「发起改约」按钮（按钮状态根据权限和工单状态自动启用/禁用）
2. **上门改约 Tab** → 查看所有改约申请、撤销改约、筛选、查看确认日志（撤销/确认按钮仅在满足条件时可用）
3. **导入导出 Tab** → 支持改约申请 CSV 导入，改约申请/确认日志 CSV/JSON 导出

**维修员（李维修 u002 / 王维修 u003）** 登录后可操作：

1. **工单列表 Tab** → 选中自己被派单的工单 → 点击「到场确认」（只有被指派的工单可点击）
2. **上门改约 Tab** → 查看自己的改约申请、确认/拒绝改约

### 统一业务入口（重构后）

所有改约和到场确认的业务规则已收拢为统一的预检入口，GUI 按钮状态与底层权限严格对齐，不会出现界面可点但底层拒绝的情况：

| 统一预检方法 | 用途 | 返回值 |
| ------------ | ---- | ------ |
| `can_create_reschedule(order_id, user)` | 判断用户是否可以对某工单发起改约 | `(bool, str)` = (是否允许, 原因说明) |
| `can_cancel_reschedule(reschedule_id, user)` | 判断用户是否可以撤销某改约申请 | `(bool, str)` |
| `can_confirm_reschedule(reschedule_id, user)` | 判断用户是否可以确认/拒绝某改约申请 | `(bool, str)` |
| `can_confirm_arrival(order_id, user)` | 判断用户是否可以对某工单进行到场确认 | `(bool, str)` |

这些方法覆盖了所有业务规则：权限矩阵、改约状态流转、候选时间窗校验、重复确认拦截、到场确认可操作人等。

### 使用流程

#### 1. 调度员发起改约

1. 登录调度员账号（u001）
2. 进入「工单列表」Tab
3. 选中一条「已派单」或「处理中」状态的工单（已完成的工单不可改约）
4. 点击「发起改约」按钮
5. 在弹出窗口中：
   - 填写**改约原因**（必填）
   - 添加**候选时间窗**（至少1个，格式 `YYYY-MM-DD HH:MM`，可添加多个供维修员选择）
   - 可选填写备注
6. 点击「提交改约申请」
7. 系统自动检测：
   - 该工单是否已完成（已完成禁止）
   - 候选时间是否与该维修员其他已排程工单冲突（冲突则拒绝，提示冲突工单）

#### 2. 维修员或调度员确认改约

1. 登录维修员账号（被指派的那位）或调度员
2. 进入「上门改约」Tab
3. 在列表中选中一条「待确认」的改约申请 → 右侧会显示详情和候选时间
4. 点击「确认/拒绝」按钮
5. 弹出确认窗口：
   - 选择一个候选时间窗 → 点击「确认改约」；或
   - 填写拒绝原因 → 点击「拒绝改约」
6. 确认后：
   - 工单的 `scheduled_start / scheduled_end` 自动更新为选中时间
   - 工单历史中新增改约确认记录（可追溯）
   - 改约状态变为「已确认」或「已拒绝」

#### 3. 到场确认

1. 登录维修员或调度员账号
2. 进入「工单列表」Tab
3. 选中一条已派发的工单
4. 点击「到场确认」按钮
5. 输入到场备注（可选）
6. 系统记录到场时间、确认人、备注，并写入工单历史

#### 4. 筛选查询

「上门改约」Tab 顶部支持：
- 按**工单编号**筛选
- 按**状态**筛选（待确认 / 已确认 / 已拒绝 / 已取消 / 已过期）
- 维修员只能看到自己工单的改约申请和到场记录

#### 5. 导入导出（仅调度员）

进入「导入导出」Tab：

- **改约申请 CSV 导入**：支持批量导入改约申请，非法行（空工单、空原因、非法时间、不存在工单、结束早于开始等）会被跳过并在结果中显示行号和原因
- **改约申请 JSON/CSV 导出**：导出所有改约申请，含改约编号、工单、原因、状态、候选时间、版本号等
- **改约确认日志 JSON/CSV 导出**：导出所有确认/拒绝记录，含确认人、决定、选中时间、拒绝原因、确认时间

## 数据持久化

所有数据保存在 `data/` 目录下，JSON 格式，跨重启可恢复：

```
data/
├── users.json                         # 用户、技能、排班
├── work_orders.json                   # 工单、历史、排程时间
├── reassignment_drafts.json           # 改派草稿
├── batch_reassignment_results.json    # 批量改派结果
├── revocation_results.json            # 撤销结果
├── spare_parts.json                   # 备件档案
├── spare_part_requests.json           # 备件领用申请
├── spare_part_audit_logs.json         # 备件操作日志
├── reschedule_requests.json           # 改约申请（新增）
├── reschedule_confirm_logs.json       # 改约确认日志（新增）
├── arrival_confirmations.json         # 到场确认记录（新增）
└── config.json                        # 导出目录配置
```

导出文件默认保存在 `./exports/`，可在「导入导出」Tab 修改。

## 安全与权限

所有写操作均通过 `ROLE_PERMISSIONS` 权限矩阵校验，关键规则：

- 只有**调度员**可以：派工、改派、发起改约、撤销改约、导入改约数据、管理备件
- 只有**工单指定维修员**或**调度员**可以：确认/拒绝改约、到场确认
- **维修员**只能看到：自己的工单、自己的改约申请、自己的到场记录、自己的备件申请
- **验收员**只能：验收工单、导出数据，不能做派工/改约/确认/到场等操作
- **重复确认不覆盖**：已确认/已拒绝的改约再次提交会被拒绝，保留首次结果
- **并发版本控制**：工单 `version` 字段 + `RLock` 保证多线程同时操作时数据一致
